> **Status:** Core contract coverage added; adapter and end-to-end rows remain planned

> **Interpretation:** Scenario cells describe the assertions actually exercised when an owning test is present. `Not covered` is an explicit remaining risk; an owning test may cover only the listed slice of a broader contract.

Every public contract or documented invariant has an owning row. A feature
change must replace the planned owner with the actual test and keep all
applicable scenario columns populated. `—` means the category is not
applicable to that contract; `Not covered` means the behavior is currently an
explicit untested risk.

## Current untested behavior

The core unit slice intentionally leaves these behaviors for later phases:

- Full engine execution, including extractor cancellation, concurrent typed
  pipeline isolation, output delivery semantics, replay network isolation, and
  runtime lifecycle start/stop ordering.
- Transport, redirect, public-network safety, robots, XML discovery, cookies,
  scheduler, events, web adapter, PostgreSQL adapter, migrations, and
  database-backed recovery.
- File-output rotation/acknowledgement, concurrent file-store writes, durable
  outbox delivery, and durable retention.
- Atomic enqueue-plus-checkpoint transactions, concurrent checkpoint winners,
  durable health/eligibility recovery, and restart guarantees beyond the
  in-memory/file tests listed above.

These are explicit untested risks, not passing coverage claims. Future feature
phases must add tests to the owning module and update the corresponding row
and this section in the same change.
